# 简历量化填写模板

项目名称：企业级多 Agent 知识管理系统（AgentKnowledgeHub）

角色：[独立开发 / 核心开发]

技术栈：Python / LangGraph / Neo4j / ChromaDB / FastAPI / Kafka / Docker

项目描述：

设计并实现面向企业文档的多 Agent 知识管理系统，打通多模态解析、知识图谱构建、混合检索问答和 CDC 增量更新链路。

核心工作：

- 基于 LangGraph 设计 [Agent 数] 类职责 Agent 与 [流水线数] 条多节点工作流，支持条件路由、并行分支、自动重试、失败回滚和 Checkpoint 恢复。
- 支持 [格式数] 类文档格式，分别处理文本、表格与图片模态，并通过 [融合方法] 完成跨模态检索。
- 在固定 [题数] 题、seed=[种子] 的配对实验中，将 [检索指标] 从 [基线] 提升至 [结果]（+[百分点] pp）；同时报告最终 Answer EM、引用指标和 95% CI，避免把检索命中率写成回答准确率。
- 通过稳定 Chunk ID、Kafka 幂等事件和跨存储一致性校验实现增量更新；在固定 [事件数] 个 CDC 事件上，相比全量重建减少 [Embedding token]、更新延迟由 [基线] 降至 [结果]。
- 建立 Ruff、单元/集成/E2E 测试和 CI，核心模块覆盖率 [覆盖率]，Docker 依赖健康检查 [通过数]/[总数]。

## 当前项目可填写的数据

- 固定 100 题：Vector All-evidence Hit@10 `45.33%`，Hybrid `50.67%`，提升 `5.34 pp`。
- Hybrid Evidence Recall@10 `76.78%`，Vector `74.44%`。
- Hybrid Answer EM `57.33%`，Vector `60.00%`；该项不能写成提升。
- v5 配对 Answer EM 差值的 95% CI 为 `[-10.67, 5.33] pp`，统计上不能说明 Hybrid 更优。

## 填写规则

1. 先写清数据集、样本量、随机种子、Top-K 和基线，再写结果。
2. 检索、回答、引用、拒答、延迟分别表述，不混称“准确率”。
3. 只有配对结果和置信区间支持时，才写“显著提升”。
4. 未完成规模压测时，不写“千级文档实时问答”；未做全量重建对照时，不写 CDC 提升百分比。
